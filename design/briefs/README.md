# design/briefs

**Jobs for the Design desk. Echo reads this folder; her answers come back as GitHub
issues on this repository.**

    OPEN/     briefs waiting to be worked
    DONE/     briefs whose answer has come back and been ruled on

## How a brief works

**C1 writes it. Nobody else.** A brief is an order to a desk, and orders come from
architecture.

**Every brief opens with WHAT WE ALREADY HAVE.** That is the one thing an outside desk
cannot know and the reason five features in this project have been designed twice. It
costs one search and it is not optional.

**Every brief says what is NOT being asked**, because a design desk with a blank edge
fills it in.

## How an answer comes back

**As a GitHub issue on this repository**, titled with the brief's id and subject.

**Never as a pull request.** An issue is a letter; a pull request is a change. Design
produces designs and recommendations and does not execute.

**The issue body ends with the end marker `--- END OF ANSWER ---`.** An answer without
it is treated as truncated and sent back rather than acted on.

## What never goes in a brief

**Nothing about rights, the Fan Kit, trademark, credentials, money, or anything from the
Looking Project.** A connected app receives what the conversation supplies, and those
subjects are the owner's alone.
