# AAR — four questions for Echo (brief section)

**Not a Claude skill.** Paste into a brief when Architecture wants an after-action from Echo.

Same standard as `claude/PROCEDURE_the-after-action-report-2026-09-12.md`.

## Instructions for Echo

Answer all four, briefly. Question 4 must be checkable by looking at a file, issue, or UI — not "be more careful."

1. **What was supposed to happen?**
2. **What actually happened?**
3. **Why was it different?** (the mechanism)
4. **What do we do differently next time?** (one checkable change)

Classify each takeaway:

- **Rule** (breaking it is wrong) → should become / amend a CLAUDE.md rule; do not only journal it.
- **Lesson** (slower, not wrong) → store in `claude/LESSONS.md`.
- **Job** (control or tool change) → name the job; do not call it a lesson.

Do not browse the open web to invent the AAR. Use the brief materials and what you already answered.
