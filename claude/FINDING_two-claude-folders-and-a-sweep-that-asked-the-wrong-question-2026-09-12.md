# FINDING — two `claude/` folders, a sweep that asked the wrong question, and a package result that contradicts a standing ruling

**Filed 2026-09-12 from CIC's report on the package sweep, with the Adjutant desk's
assessment. CIC's own words are preserved below. Read-only; nothing was modified.**

## 1. TWO FOLDERS WITH THE SAME NAME, AND THE RECEIPT DOES NOT SAY WHICH

**CIC's finding, and it is the most valuable thing in the report.** There are two `claude/`
folders — the claude.ai project store and the repository on his machine — with the same name
and the same filenames, and **the write receipt does not say which one it wrote.** The
253-row roles file went to the project store. Four documents cited it, Build could not find
it, and Q63.8A sat blocked.

**Why it matters beyond one file:** this is the third instance of one shape. A design filed
in the project and not on disk cost two desks nine and a half hours. The Adjutant desk read
the front page's data and called it the project, twice. **Now a file announced by name
existed on a machine the reader could not reach.**

**CIC's own point, which is the sharp one:** Architecture's lag test could never have caught
it. Waiting longer does not produce a file that is on another machine.

**The rule this earns:** a path in a memo names the machine, and the writer reads the file
back from disk before citing it. A receipt is not a location.

## 2. THE SWEEP RIDER THAT COVERAGE CANNOT GIVE YOU

CIC's first pass was wrong on six of 253 rows **and reconciled perfectly.** The test required
a sentence to end in a full stop; RSI's bullet lists carry no punctuation, and a bullet list
is exactly where a ship says what comes with it.

**"The standing rider we adopted — reconcile against a known list — proves every row was read
and says nothing about whether the right question was asked."**

**Adopted: every sweep carries one row whose answer is known from outside the sweep.** That
is a new method rule and it belongs beside the standing-pass method, not buried in a result.

## 3. THE RESULT CONTRADICTS A RULING WE ARE DESIGNING AGAINST — DO NOT BUILD ON EITHER YET

CIC reports the package job came back clean: **none of the 253 rows is a package, and nothing
any ship contains is missing from the catalogue.**

**Sleven ruled the opposite three hours earlier, in his own words:** *"the [Carrack]
Expedition is just a extended package with those ships packaged together... we provide all
the information for each one of those ships anyway. So that one is not necessary."* The
package section, the "Packages containing this ship" design and the three answers Echo gave
all rest on that.

**What our own data says, read today:** the Carrack Expedition row is `pledge_only`, carries
no store link, and its note is the generic "Flight-ready, no dealer." **Its 3D model file is
byte-identical to the Carrack's** — 876,628 bytes each. That is edition-shaped, not
bundle-shaped.

**What nobody has done: read RSI's own Carrack Expedition page and written down what it
actually includes.** Until somebody does, we have a ruling and a sweep that disagree, and
both are being designed against.

**This is the carrying-out-an-order-whose-premise-is-wrong trap, and it is live.** The right
move is one primary-source read, not an argument.
