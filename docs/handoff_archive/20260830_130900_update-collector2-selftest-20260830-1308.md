# Update — collector2 self-test: two real defects, both fixed, 30/30 green

`go build` + `--self-test` on Sleven's personal collector2 build. Three failures
went in; **two genuine defects came out**, and the second one was a silent success
in the assertion the program exists for.

## Build first: two unrelated pairs both named before/after

`collector2` is not in `go.work`, so it builds with `GOWORK=off` — the workspace
was left alone. That surfaced a compile error: `selftest.go` held `before`/`after`
as `os.FileInfo` (measuring append-only growth by bytes) and redeclared the same
names as `int` counters in the same scope. Renamed the counters to
`believedBefore`/`believedAfter`, which says what they count.

## Defect 1 — a crash mid-write silently ate the NEXT observation too

`store.go`'s `Record` opened `O_APPEND` and wrote `json + "\n"`. Correct only if
the file already ends in a newline — which is exactly what a crash mid-write
does NOT leave. The next `Record` landed **on** the partial line and produced one
line that was neither observation: unparseable, skipped by `Each`, gone with no
error anywhere.

The file's own header claimed the opposite: *"a crash mid-write costs the tail of
one line and nothing before it."* True for everything before it. **The line after
it was being lost as well, and nothing reported that.**

Fixed: `Record` opens `O_RDWR` (still `O_APPEND`, so no seek can land on existing
bytes), reads the last byte, and starts a fresh line when the file does not end
on one. The truncated line stays truncated and stays skipped — inventing the rest
of a line nobody wrote is worse than losing it. What it must not do is take a
healthy observation down with it. Header corrected to what the code now does.

Three assertions failed on this and now pass, which is the proof in both
directions: the self-test WAS the known-bad input.

## Defect 2 — the headline assertion was passing on the wrong answer

With those green, three more surfaced. `derive.go:119` builds the taught
vocabulary keyed on **text alone** — `lex[lower(a.Text)] = a.Answer` — discarding
Kind and Source. So the unknowns-pile section's answer (Quantanium → Quantainium,
for a `shop_row` from `kiosk@1`) was already rewriting the `shop_transaction`
readings `kiosk@3` takes 100 lines further down.

By the time the teaching block ran its FIRST `Derive()`, the correction had
already happened. So **"ONE ANSWER REACHED A READING TAKEN BEFORE IT WAS GIVEN"
— the assertion the file calls the whole point of the program — was passing on
the earlier section's answer, not the one under test.** The proof was sitting two
lines below it: the "REPORTS what moved" assertion said nothing moved, because
the answer being tested had nothing left to change.

Fixed in the test, not the design: the block now uses a misreading nobody has
answered (Astatinne → Astatine), so the only answer that can move it is its own.

**The global-by-text vocabulary is left exactly as it was.** It is defensible —
teaching once reaching everywhere is what the program is for. But it is now
ASSERTED rather than relied on by accident: a new check records one answer
reaching across kinds, so scoping it later fails a named check instead of quietly
gutting the teaching block again.

Mutation-tested: scoping `lexicon()` by kind fails ONLY the new cross-kind check
and leaves the teaching headline green — the two are independent and the new one
is precisely aimed. Reverted, rebuilt, verified clean.
