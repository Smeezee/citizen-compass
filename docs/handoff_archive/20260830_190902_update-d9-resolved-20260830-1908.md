# Update — D9 resolved, and it was never a parser discrepancy

Took a DEFERRED item, since that list is worked when a build front is finished
and mine is. **D9: the collector says 289 item transactions, the Python miner
says 286.**

## It disagrees in BOTH directions, which "three more" hid

Compared as a multiset on the fields both sides carry and neither invents —
itemClassGUID, client_price, quantity, shopName:

    7 rows in Go, not in Python
    4 rows in Python, not in Go

**Net +3, which is what the DEFERRED line recorded, and it is a coincidence.**
Two instruments reading different corpora three weeks apart.

    Python   2026-08-07, 233 sessions, "LIVE and PTU logbackups"
    Go       today, 243 files, LIVE only

**There is no PTU install on this machine any more.** So the four Python-only
rows are PTU sessions whose logs are gone, and the seven Go-only rows are LIVE
sessions logged after the Python dig. Nothing is being mis-parsed.

## The part worth keeping

Those four PTU transactions now exist **only** as rows in the Python miner's
output. The raw logs cannot be re-read by anything, ever.

**That is exactly the argument `archive.go` was built on** — a better reader
cannot run over a session nobody kept. The archive is what stops it recurring;
this particular loss predates it by three weeks. Recorded in `DEFERRED-BUILD.md`
under Closed with the full reasoning rather than a one-line "resolved".

## A real defect found on the way, and it is Architecture's

I could not use timestamps as the comparison key, and the reason is a defect:

    // At is when it was SEEN, not when it was written.   <- store.go says this

    {"at": "2026-08-30T20:25:34Z", ...}                   <- a transaction read
                                                             out of a months-old
                                                             logbackup

`read_gamelog.go` has **no timestamp pattern at all** — `reBuild`, `reLoc`,
`reAward`, `reTxn`, `reField` and nothing else — so `At` is never set and
`Record` fills it with `time.Now()`. All 633 observations from 243 archived
sessions claim to have been seen within the same few seconds.

`derive.go` writes `f.Data["last_seen"] = o.At`, so **every fact says it was last
seen today.** A price from January and one from last week are indistinguishable
on the only field that separates them.

Every log line carries an RFC3339 timestamp in angle brackets, which is where the
rock reader already gets its lines. **Memo sent; I changed nothing in
`collector2/`.** I also said what I did NOT check — whether every transaction
line carries a parseable timestamp in every build in the archive — because a line
without one needs a decision rather than a default.
