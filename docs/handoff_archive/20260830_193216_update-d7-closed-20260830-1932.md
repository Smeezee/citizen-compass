## The defect

`json.Unmarshal` into a struct **silently discards keys it does not recognise.**

    "intervall_hours": 1     ->  thrown away without a word
                                 watcher polls on the 4-hour default
                                 the file on disk says 1 hour
                                 the operator believes the file

**The settings file is gitignored**, so no review of the repository could see the
divergence either. A misspelling would have survived indefinitely, and the
symptom would be "the watcher ignores my settings" with nothing to point at.

## The fix, and the two things it deliberately does not do

`rejectUnknownKeys` refuses a settings file carrying a key the program does not
read, and **names it**.

**It tolerates `_`-prefixed keys.** The live file carries `_boards_note` and
`_watch_note`, recording why board 2 was dropped (its own payload says it will
not be updated) and why `watch` is `"*"`. A blanket `DisallowUnknownFields`
would have deleted the only place that reasoning lives — the file is not
committed, so it cannot live in a commit message either.

**The known set is derived by REFLECTION over the struct, never typed out.** A
hand-written list is a second thing to update when a field is added, and the day
somebody forgets, the guard refuses a perfectly valid setting. That is how a
guard becomes an obstacle and then gets switched off.

## Proven, not asserted

Four tests. **Both directions:**

    guard removed          -> fails the misspelling test, and ONLY that one
    `_` keys refused too   -> fails the notes test

One of the four asserts the program can re-read **the settings file it writes
itself**, so writer and reader cannot drift into the watcher refusing its own
default file on a machine that has run once.

**Verified the live file still loads** rather than assuming: 9 keys, 8 real plus
2 notes, none refused. `go vet` clean.
