# Update — the one-fleet control is written, green, and proven able to fail

`checks/_verify_one_fleet_two_files.py`. C1 said yes on 09-05 and set two
conditions; both are in it.

## What it holds

`releases/latest.html` (what `build_deploy.py` reads to build TESTING) and
`static/preview.html` (what the LIVE site serves) must describe the same fleet.
**254 ships each, PASS ship for ship and field for field.**

Editing one and not the other produces no error and no red control anywhere. It
produces two sites quoting different numbers, found by a visitor.
`_verify_version_single_source.py` already held them to one version string;
nothing held them to one fleet.

## Parsed, not bytes — and every field, not a chosen few

Keyed on `id`. Not name (the site's own display text, and edited) and not array
position (not a key at all).

C1 said "the fields that matter". **I compare all of them**: there is no field
where a difference between these two files would be acceptable, and picking
favourites now is how a gap opens later. Byte comparison was ruled out for C1's
reason — it would go red the first time somebody reformats one, and a control
that cries wolf gets ignored.

## Rule 12 — five plants, negative control FIRST

    ok      untouched copies                   silent
    caught  one ship's price changed           disagrees on 'auec_price'
    caught  and it names the ship              129 / 100i
    caught  a ship dropped from one file       on the LIVE fleet and not TESTING
    caught  the array missing altogether       carries no SHIPS literal
    caught  the array present but malformed    not valid JSON, refusing to guess

The untouched-copies check runs first and **aborts the whole self-test if it
fires** — without it, every "caught" could be a control that always complains.

**The price plant failed on the first run and refused to report a pass:** *"PLANT
FAILED - could not find a price to change. The self-test proved nothing;
treating as failure."* The literal is compact JSON (`"auec_price":1089270`, no
space) and `json.dumps` defaults insert spaces, so it matched nothing. A plant
that silently misses is a self-test proving the opposite of what it claims.

## RED, not report-only

`_verify_front_page_prices.py` is report-only because it raises a data question
nobody has ruled on. **This one is a defect with a known remedy**, and the person
who finds it otherwise is a visitor comparing two sites. It should stop a deploy.

## The limit, stated in the header rather than left implied

**It asserts AGREEMENT, not correctness.** Edit both files the same wrong way and
it passes. There is no generator behind the array — C1 confirmed it is a
hand-maintained literal — so there is no third source to check against. What it
rules out is the failure that actually happens: one edited, the other forgotten.
