## THEN THE TRAYS WENT WRONG, WITHIN MINUTES

**Answering a memo left the original in the open tray.** The same question
existed twice:

    open/owner/...watcher-binary-swap.md   4595 bytes  Status: Open
    answered/...watcher-binary-swap.md     5984 bytes  Status: Answered

An answered question still read as waiting. The tray stopped meaning what it
says, which is the only thing a tray is for.

**`TestAnAnsweredMemoLeavesTheOpenTray` did not catch it, and its NAME is why it
looked covered.** It asserts `memoDestination` RETURNS a path containing
"answered" and not "open" — where the memo GOES. Nothing asserted it LEAVES
anywhere, because nothing touched the filesystem. The name claimed the
behaviour; the body checked a string.

### Fixed in memo.go — `watcher-go/` is mine, so I took it rather than filing it

Filing an answered memo now sweeps a same-named copy out of the open trays.
**Moved to `_to_delete/` with a timestamp, never deleted (rule 1)**, so an answer
filed against the wrong original stays reconstructable. The sweep runs only AFTER
the answered file lands — if `routeTo` fails the original must stay put rather
than be moved aside for an answer that never arrived.

Two tests, and the second matters as much as the first:

    TestAnsweringActuallyEmptiesTheOpenTray  touches the filesystem, which is
                                             where the defect was
    TestNothingIsSweptWhenNoOpenCopyExists   the sweep is keyed on FILENAME, so
                                             this is the case where a same-named
                                             document silently empties a tray

Mutation-tested: restoring the pre-fix behaviour fails the first and only the
first — `clearOpenCopy reported "", want "build"`.

## ONE MORE, IN MY OWN SCRIPT, SAME DEFECT CLASS

My answer-writing script used `partition("ANSWERS:")` and matched the memo's own
INSTRUCTIONS — *"under a line reading `ANSWERS:`"* — instead of the reply line,
then reported the memo as already answered. **Matching a token anywhere rather
than where a header can legally be: the exact thing the router's 4,000-byte cap
and line anchoring exist to prevent.** Now anchored to `^ANSWERS:$` and taking
the last match. The control was never affected — it already anchors to line
start — but I only knew that because I went and checked.
