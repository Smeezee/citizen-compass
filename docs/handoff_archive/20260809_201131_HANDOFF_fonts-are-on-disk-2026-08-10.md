## 2. The licence question is answered, and answered from the source

Code's README said, correctly, *"all three families are, to the best of my
knowledge, published under the SIL Open Font License. VERIFY THAT before shipping
rather than taking it from an AI assistant."*

Verified — by reading the `LICENSE` file shipped inside each font's own
distribution package, not from a web page and not from recollection:

    Saira Condensed   SIL Open Font License 1.1   Copyright 2016 The Saira Project Authors
    Rajdhani          SIL Open Font License 1.1   Copyright 2014 Indian Type Foundry
    Chakra Petch      SIL Open Font License 1.1   Copyright 2018 The Chakra Petch Project Authors

**What the OFL permits:** free use commercial or not, embedding in a website,
redistribution. No cost, no purchase, no registration.

**What it requires:** the licence text travels with the fonts. That is what
`OFL.txt` is for and it must sit in the same directory as the `.woff2` files.

**Reserved Font Names:** "Saira" is reserved by its authors, which restricts
*modified* versions from carrying the name. These files are unmodified — only the
filenames differ, to match what `keybinds.src.html` asks for — so the restriction
is not engaged. Renaming a file does not rename a font.

Sleven has been told all of the above and asked for the fonts. **The decision to
ship them is his and has been made; this is the record of it, not a request for
it.**

## 3. What Code does

Copy the five files into `testing/_deploy/fonts/` and rebuild. **No code change is
needed:**

- `keybinds.src.html` already declares the `@font-face` rules pointing at these
  exact names.
- `check_deploy_clean.py` already has `fonts` in `DEFAULT_ALLOWED_DIRS`.
- There is no copy step to add — `_deploy/images/` and `_deploy/models/` are not
  copied from source either, they live there and the build reads them from there.
  Code established that in the pass-2 update and it applies here unchanged.

`README.txt` should stay, but its "THIS DIRECTORY IS INTENTIONALLY INCOMPLETE"
opening is now false and wants rewriting to describe what is there.

## 4. The recommendation that came with the decision still stands

Code's split, which I would back: **Star Citizen faces on chrome only** —
headings, tab labels, panel titles, buttons — with the 691-row action table left
on the system stack.

The reason is unchanged and is not cosmetic: `keybinds.src.html` carries no font
control of its own, so whatever the table is set in is what every reader gets with
no way out. Saira Condensed is a condensed face and condensed faces are harder to
read at low vision, not easier. Putting it on the densest small text on the site
would be the wrong trade.

## 5. What I checked and what I did not

**Checked:** the LICENSE file inside all three distribution packages; the `wOF2`
header on all four output files; the exact filenames against
`_deploy/fonts/README.txt`; that the Fan Kit's own three fonts (Banu, xiinchil,
xiinthlea) are alien-alphabet display faces and cannot serve as UI text, so they
were not an alternative.

**Did NOT check:**
- **How these render on the actual page.** Nobody has seen the keybind page in
  these faces; the fallback is what has been looked at so far.
- Whether the latin subset covers everything the page needs. It covers latin;
  if any key name or label uses a character outside that range it will fall back
  for that glyph. Not observed, but not ruled out either.
- I am not a lawyer and this is not legal advice. What is recorded above is what
  the licence files say, read directly.
