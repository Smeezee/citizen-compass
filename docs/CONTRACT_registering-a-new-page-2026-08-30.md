## 1. THE SHORT ANSWER: FILES FIRST, THEN THE SLOT, IN ONE CHANGE

**"Register the slot and I will fill it" is not available**, and that is
deliberate rather than an oversight. `build_deploy.py` refuses a registered page
whose source is missing:

    PAGE SOURCE MISSING: %s
    index.html was written but these pages were NOT copied, so any link
    to them would 404. Fix the source or remove the entry from PAGES.
    Failing loudly rather than shipping a page with dead links.

An empty slot would break **every build** until the files landed, including
builds nobody had connected to your work. So: hand me the files, and the slot
lands in the same commit as the thing that fills it.

## 2. WHERE THE SLOT IS, AND IT IS ONE PLACE

`testing/_src/deploy_pages.py`, the `PAGES` list. Two entries for a page with a
data file:

    ('commodities.src.html',    'commodities.html'),
    ('commodity_data.gen.js',   'commodity_data.gen.js'),

`(source in testing/_src, name written into testing/_deploy)`.

**Nothing else needs editing.** The build copies from this list and the deploy
guard permits from this list - the same sentence, not two that agree. That file
exists because there used to be two lists kept in step by hand, and they drifted
twice.

## 4. SIX THINGS THAT WILL BITE, EVERY ONE OF THEM MEASURED THIS WEEK

**a. COMMENTS DO NOT SHIP.** Q31 strips every comment on the way into `_deploy`.
Write as many as you like in `_src` - they are the best documentation this
project has - but **the page must not depend on a comment at runtime.**
`_verify_display_names.py` read its snapshot id out of a header comment and went
red the day the strip landed; it now reads `LOADOUT_META.snapshot` from the
payload, which is the right shape.

**b. THE `.gen.js` HEADER MUST NOT NAME THE GENERATOR.** `GENERATED by
build_commodity_data.py` names a build script and the repo layout on a public
URL. The strip removes it from `_deploy`; keep it in `_src`. A control asserting
that header must assert it on the `_src` copy - two controls asserted it on the
served copy and both had to be moved.

**c. A PUBLISHED CHECKSUM MUST DESCRIBE THE SERVED BYTES.** If the page offers a
hash for a downloadable data file, compute it AFTER the strip. The find page
published a sha256 of its `_src` file, the strip removed 1,169 bytes, and the
site told visitors their correct download was corrupt. `build_deploy.py` now
recomputes that one; a second such page needs the same treatment and I will wire
it.

**d. NO PRICES IS A FEATURE - SAY SO ON THE PAGE.** "CIG ships none" is exactly
the honest gap this site is for, and the find page's wording control exists
because a page that says less is the failure worth catching. **Put the absence
in the visible copy**, not only in a doc. If you want it guarded, tell me the
sentence and I will assert the CLAIM rather than the wording - four controls
this week pinned prose and went red when the prose improved.

**e. THE PAGE GETS THE TRADEMARK STRIP APPENDED AUTOMATICALLY**, and the
disclosure CSS if it carries `/* CC_DISC_CSS */`. three.js is inlined only if
the page carries `<!-- CC_VENDOR_THREE -->`. Do not paste either by hand; both
are declared injections the drift control knows about, and a hand-pasted copy
reads as a hand edit.

**f. EVERY INLINE SCRIPT MUST PARSE**, checked by `node --check` before and after
the strip. A `<script type="application/json">` data island is left alone -
that is data, not JavaScript - so use that type if you embed JSON literally.

## 5. WHAT THE PAGE OWES A READER, GIVEN WHAT IT IS

206 commodities, 30 refining pairs, mining resistance and instability per
material, 6 gadgets and 8 modules, **and no prices**.

The one thing that would make this page worse than useless is a reader assuming
the numbers are live. `last_verified_patch` is on every row of the ship page for
that reason. **Say which patch the commodity figures came from, in the markup,
from the data layer rather than a constant** - the roadmap watcher now reports
the gap between the live patch and what the site claims it verified, and a page
carrying a hardcoded patch string would sit outside that check entirely.
