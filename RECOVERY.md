# RECOVERY — what survives if this machine does not

Written 2026-08-02 before the machine is disassembled and moved to Minnesota.

**Read this first if the drive did not survive the move.** It says what is gone, what is recoverable, and in what order to get it back. Nothing in this project is truly irreplaceable — but some of it is slow, and the order matters.

---

## The short version

**Four things already live somewhere other than that machine:**

| what | where it survives |
|---|---|
| all code, docs, manifests, work orders | **GitHub** — `Smeezee/citizen-compass` |
| the PostgreSQL database | **Railway** — never was on the machine |
| the testing site build | **Cloudflare** — `citizencompasstesting.citizencompass-contact.workers.dev` |
| the live site | **Netlify** — `citizencompass.netlify.app` |

**So the code, the record, the database and both deployed sites are already safe before anything is unplugged.**

What is only on the machine is **data that can be re-acquired** and **secrets that can be re-issued**. Both cost time, neither costs work.

---

## What is only on that machine

### `sc-ships/` — 7.3 GB, 243 ship folders, gitignored

3D models and images. **Re-downloadable.** `sc-ships/README.md` is a Hugging Face dataset card naming the source — "Star Citizen Fan Assets (Unofficial)". Re-clone it.

**Cost:** a long download. **Loss:** none, unless the upstream repo disappears — which its own takedown policy makes possible. If that has happened, the models are genuinely gone and the 3D viewer would need a different source.

### `data-layer/external-sources/` — the sealed snapshots, gitignored

Sources 1, 2, 3 and 6. **All re-acquirable**, and the retrieval scripts are committed under `scripts/external_sources/`.

**The important part: the provenance chain survives.** 33 manifests and 23 verification hash sets are committed. So a re-acquired snapshot can be checked against the hashes of the one that was lost — you would know whether upstream changed, rather than having to trust it.

**Source 1** is a git clone of upstream commit `4764726` — re-cloneable, and the commit is recorded.
**Source 6 (UEX)** needs the API token. Re-issue it (see below) and re-run `scripts/external_sources/uex_corp.py`.

**Cost:** hours, mostly waiting. **Loss:** none.

### `data-layer/processed/` — the craft output

Not gitignored, but only 5 files are tracked. The rest — 1,597 blueprint pages, 724 source files, the indexes — **are regenerated by `scripts/split_craft_pages.py` from the sealed snapshots.**

**Cost:** minutes, once the snapshots are back. **Loss:** none.

### `testing/_deploy/` — 349 MB, gitignored

`index.html` is regenerated by `testing/_src/build_deploy.py`. The models and images are derived from `sc-ships/` by `testing/_tools/cc-compress.cjs` and `mk_thumbs.py`, both committed.

**And Cloudflare is currently serving a complete copy of it.** Worst case it can be pulled back down from there.

**Cost:** a long compression run. **Loss:** none.

### `.env` — three secrets, one machine, no backup

`DATABASE_URL`, `UEX_API_TOKEN`, `CLOUDFLARE_API_TOKEN`.

**Every one is individually re-issuable:**

- `DATABASE_URL` — read it from the Railway dashboard
- `UEX_API_TOKEN` — regenerate at `uexcorp.space/api/apps` (this one was due for rotation anyway)
- `CLOUDFLARE_API_TOKEN` — roll at `dash.cloudflare.com/profile/api-tokens`, scoped to `Account → Workers Scripts → Edit`

**Cost:** ten minutes. **Loss:** none.

**This is the one item with no backup at all, by design — a secrets file must never be in an unencrypted backup.** The right long-term answer is a password manager, and it remains open.

## Recovery order, if it comes to that

1. `git clone` the repo. Everything below rebuilds from there.
2. Rebuild `.env` from the three dashboards.
3. Re-acquire the snapshots with the committed retrieval scripts. **Verify each against the committed manifest hashes** — that is what the manifests are for.
4. Re-clone `sc-ships/`.
5. Run the compression and thumbnail passes to rebuild `testing/_deploy/`.
6. Run `scripts/split_craft_pages.py` to rebuild `data-layer/processed/`.
7. Run `python testing/_src/build_deploy.py`, then `scripts/deploy_testing.ps1`.

**Nothing in that list requires a decision.** It is all mechanical, and every step's script is committed.

---

## The honest gap

**There is still no offsite backup, and this move is exactly the scenario it exists for.**

The mitigation is that everything is either committed, deployed, or re-acquirable — which is why this document can promise no work is lost. But it is a mitigation, not a backup: it trades a drive failure into a day of re-downloading rather than into nothing.

**The open decision on Stage 3 archival storage is still open.** If it had been taken, this document would be one line long.

---

## What to do before powering down

1. **Commit and push everything.** The repo is the backup.
2. **Confirm `git rev-parse HEAD origin/main` returns the same hash twice.** That is the whole safety net in one command.
3. **Confirm the Cloudflare site still serves** — that is the offsite copy of the deploy build.
4. Leave this file in the repo root.
